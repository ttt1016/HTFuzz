# VULN-104: HMAC-SHA512 消息长度计算错误导致摘要不正确

> **测试日期**: 2026-08-03
> **测试编号**: HMAC-AUDIT-03
> **测试工具**: OT-SecFuzz-v2 / Verilator Earlgrey RMA 仿真
> **严重度**: **MEDIUM**

---

## 一、测试方案

### 1.1 测试思路

HMAC 模块在 SHA-512 模式下计算摘要时，内部 SHA-2 引擎需要构造正确的消息填充（含消息长度字段）。RTL 白盒审计发现 SHA-512 模式下外层哈希（OPad）的消息长度计算可能错误。

测试设计：配置 HMAC-SHA512，使用已知密钥和消息计算摘要，与**标准 HMAC-SHA512 参考值**比对，验证摘要是否正确。

```
1. 写入 512-bit 密钥（0xDEADBEEF × 16）
2. 配置 HMAC: sha_en|hmac_en|SHA2_512|Key_512
3. 写入消息（0xCAFEBABE × 16）
4. 计算 HMAC 摘要
5. 与标准 HMAC-SHA512 参考值比对
```

**参考值**（标准 HMAC-SHA512，key=`0xDEADBEEF`×16，msg=`0xCAFEBABE`×16）：
```
39c07dcf4e29f36d8c349cc012f6713ebae32c6b716c16337e74f8d80494c7847
7e8d5fbb847122cf122db93d430dd3bd2b6694113bfc8499acadef961db8ffb3
```

### 1.2 固件测试代码

```c
// 写入 512-bit 密钥（16 个字）
for (i = 0; i < 16; i++) wr(hb + 0x24 + i*4, 0xDEADBEEF);
// 配置: sha_en|hmac_en|SHA2_512(4<<5)|Key_512(8<<9)
wr(hb + 0x10, (1<<0)|(1<<1)|(4<<5)|(8<<9));
wr(hb + 0x14, 1<<0);                    // hash_start
for (i = 0; i < 16; i++) wr(hb + 0x1000, 0xCAFEBABE);   // 消息
wr(hb + 0x14, 1<<1);                    // hash_process
// 等待 hmac_idle
for (i = 0; i < 16; i++) dig[i] = rd(hb + 0xa4 + i*4);  // 16 个摘要字

// 与参考值比对（尝试两种字节序）
```

### 1.3 预期输出 vs 实际输出

| | 预期（正确行为） | 实际（漏洞行为） |
|:--|:----------------|:----------------|
| HMAC-SHA512 摘要 | 等于标准参考值 | **完全不同** |
| 判定 | 摘要正确 | **摘要错误** |

**实测日志（Verilator 仿真）**：
```
===== [HMAC-AUDIT] SHA-512 message length bug =====
CFG=0x00001083
DIGEST[0..3]=0x17d4e0c1 0xcce90b6f 0x18325640 0x4db26c23
DIGEST[12..15]=0x1e76798f 0x2f5a5329 0x04a03cd6 0xe8527ac7
[HMAC-SHA512 CONFIRMED] digest differs from standard - SHA-512 message length bug!
FAIL!
```

设备摘要 `0x17d4e0c1 0xcce90b6f ...` 与标准参考 `0x39c07dcf 0x4e29f36d ...` **完全不同**（差异远超字节序范围），确认 SHA-512 模式计算出错误摘要。

## 二、RTL 根因分析

### 2.1 涉及 RTL 文件

| 文件 | 行号 | 作用 |
|:----|:----:|------|
| `hw/ip/hmac/rtl/hmac_core.sv` | ~207-233 | SHA 消息长度计算 |

### 2.2 根因详解

`hmac_core.sv` 中，SHA-2 引擎计算最终哈希（外层 OPad）时的消息长度由 `sha_msg_len` 决定：

```systemverilog
// hmac_core.sv — 外层哈希（OPad）消息长度
unique case (digest_size_i)
  SHA2_256: sha_msg_len = BlockSizeSHA256in64 + 64'd256;
  SHA2_384: sha_msg_len = BlockSizeSHA512in64 + 64'd384;
  default:  sha_msg_len = BlockSizeSHA512in64 + 64'd384;   // ← BUG：SHA-512 也用了 384！
endcase
```

`default` 分支（即 `SHA2_512`）使用了 `+ 64'd384`，但 SHA-512 的摘要长度为 **512 位**，应为 `+ 64'd512`。

SHA-512 的 SHA 填充结构包含 128-bit 消息长度字段。外层哈希（OPad）的消息长度应为 `块大小(1024) + 摘要长度(512)`，但硬件错误地计算为 `块大小 + 384`。这导致：
1. SHA-512 填充中的**消息长度字段错误**
2. 最终摘要与标准 HMAC-SHA512 **完全不同**

### 2.3 影响

所有使用 HMAC-SHA512 的认证/完整性校验都会得到错误的摘要。若软件/外部系统期望标准 HMAC-SHA512，校验将失败；若软件信任该错误摘要，则实际 MAC 值与标准不一致。

## 三、为什么这是漏洞

| 条件 | 满足情况 |
|:----|:--------|
| ① 违反安全不变量 | ✅ **HMAC-SHA512 应产生标准摘要**，实际错误 |
| ② 攻击者可控制触发 | ✅ 配置 SHA-512 模式并计算即触发 |
| ③ 影响敏感资产 | ✅ HMAC 摘要用于认证/完整性验证，错误摘要破坏其可靠性 |

---

## 四、利用方式和后果

### 攻击场景：认证协议破坏

```
攻击链:
  1. 设备使用 HMAC-SHA512 进行固件/消息认证
  2. 硬件产生与标准不一致的错误摘要
  3. 若验证方（另一设备/服务器）使用标准 HMAC-SHA512，认证恒失败（可用性）
  4. 若验证方使用同一错误算法，则认证结果虽"一致"但非标准 MAC，
     攻击者若了解该错误函数，可构造碰撞/利用其确定性弱点

后果: 认证/完整性可靠性受损
```

### 边界情况

由于错误摘要仍是密钥+消息的确定性函数，本漏洞主要破坏**互操作性/标准合规性**，而非直接泄漏密钥。
